## 1. 目的和工程哲学

本文把 00 至 09 的机械方案转换为可执行的 SimpleCADAPI 建模任务、代码边界、依赖顺序和完成判据。建模顺序采用 bottom-up：先建立可验证的零件和运动副，再组成子总成、配对总成、织造区和整机。顶层参数与骨架在开始时建立，但只发布接口，不代替底层实体设计。

核心原则：

> Make things beyond look well; we need them to work well.

因此：

1. 关键零件不得用只表达外观的包络盒替代；必须满足 [08](08-parts-assembly-and-cad-breakdown.md) 的最低几何合同。
2. 每个活动机构必须同时具有实体、运动副、机械零位、软/硬限位、工作姿态和扫掠包络。
3. 每个子总成必须能独立完成规定全行程；不得用整机位置偏置掩盖局部几何、自由度或刚度错误。
4. 供纱、偏斜索引、引纬、交接、打纬、控宽和牵引的功能边界不得互相代偿。
5. 所有载荷路径必须最终闭合到 A10 主机架；工艺接触、传动输入和反力接口必须可追踪。
6. 所有关键参数携带来源和验证状态；未知值不得静默猜测。
7. 概念 CAD 可以使用明确标识的工程建议值；加工图和 `FULL` 配置必须在对应冻结关口失败关闭。
8. 模型 JSON 是可重放几何/操作图的权威交换边界；与其 SHA-256 绑定的 evidence manifest 承载参数、数量、外部试验和发布状态。STEP/STL 只作为几何输出，不代替二者。
9. 测试、错误路径、边界条件、文档和验证报告与几何实现同批完成，不推迟到后续补齐。

## 2. 整机理解确认

### 2.1 工艺闭环

整机不是传统连续旋转织机，而是离散索引、双引纬、步进牵引的制造单元。一个完整周期为：

```text
左右插入新挂钩并进入导轨
→ A40/A41 四排偏斜导向块镜像移动一个节距 p
→ A30/A31 偏斜供纱链与导向块机械锁相，各索引一个工位
→ 三根拉剑在上/中/下通道完成 Filling A
→ 接合杆 2 捕获三只纱圈，开放式筘送至 D 成型面
→ 接合杆 1 交接，M2 驱动上下粘合针反向换位
→ 相同拉剑路径完成 Filling B 和第二次打纬/锁合
→ 所有侵入机构退出
→ A90 全宽夹具沿 +X 牵引一步 s
```

横向偏斜索引和纵向牵引共同决定偏斜角：

```text
tan(theta) = p / s
```

任何只修改 `s`、不联动 `p` 和目标角度的方案都会改变织物结构。每个完整周期固定执行两次时间上的填充插入；每次插入同时覆盖三个空间填充通道。

### 2.2 空间布局

整机统一使用：

- `X`：供纱到成品方向，`X<0` 为供纱/导向侧，`X>0` 为牵引侧。
- `Y`：织物宽度和拉剑运动方向，`Y<0` 为拉剑初始侧，`Y>0` 为拾纱侧。
- `Z`：织物厚度方向，`Z=0` 为中间填充通道和织物中面。

工艺平面严格保持：

```text
X_G < X_N < X_R < X_F=0 < X_T
```

三个填充通道关于 `Z=0` 对称：`(+H_fill, 0, -H_fill)`。A40/A41 固定框架沿 Z 镜像安装，框架本体不横移；只有导向块排、推杆和端部转层梭运动。左右挂钩按 `Y=±W/2` 的折叠线定位，拉剑在 Y 向贯穿有效宽度，牵引夹具沿 X 向移动。

### 2.3 结构和载荷闭环

主底架的两条精加工梁发布基准 A；B/C/D 分别定义宽度中心、中面和成型面。A12 供纱架、A13 织造门架和 A14 牵引架统一安装到 A11，构成以下主要力流：

```text
M1 → A42 → 导向块/供纱链 → A40/A41 → A13 → A11
M8 → 筘 X 台 → 筘座/筘片 → 成型线 → 控宽/牵引 → A14 → A11
M10 → 双丝杠 → 全宽夹具 → 织物/全部纱线 → 供纱架 → A11
```

挂钩主要承担 Y 向控宽和姿态约束，A90 夹具主要承担 X 向牵引；二者不能互相替代。开放式筘的 Z 轴只负责进出纱层，主要 X 向打纬反力必须经筘座和 X 滑台闭合到门架。中央固定经纱导向板只承担纱线导向反力，不承受导向块链推力。

### 2.4 机械正同步边界

以下关系不得仅依赖两个独立伺服的软件同步：

1. A40/A41 导向块与 A30/A31 偏斜供纱链由 A42/M1 机械锁相。
2. A80 左右挂钩由 M9 横向同步轴镜像驱动。
3. A90 左右丝杠由 M10、同步横轴和锥齿轮保持机械同步。

M2 至 M8 可由独立伺服配合虚拟主轴，但 CAD 必须表达运动自由度、零位、限位和关键离散姿态，不把虚拟时序误画成一根不存在的总机械轴。

## 3. 开工前必须显式处理的缺口

缺口不应阻止参数、架构、代表性零件和概念总成开始建模，但必须限制对应输出级别。GAP-02/GAP-03 是 A40/A41/A42 功能闭环的硬阻塞项：在其关闭前，只允许建立接口和非功能性布局样机，不允许宣称偏斜索引机构已经成立。

| 编号 | 未闭合问题 | 概念 CAD 处理 | 冻结关口 |
|---|---|---|---|
| GAP-01 | `W=288...300 mm` 与 `(n-1)p=288 mm` 的物理含义不唯一 | 单独参数化导向中心跨度、成品宽度和边缘余量 | A80、筘宽度和夹具加工图前 |
| GAP-02 | A40/A41 的 `N_block` 及 S0/S1/S2 占位表未闭合 | `REPRESENTATIVE` 只能表达接口和样本块，不得通过导向功能验证 | WP-04 偏斜索引拓扑冻结前，A40/A41/A42 功能出口和 `FULL` 均失败关闭 |
| GAP-03 | 图 3.24 的三阶段是单周期内阶段还是跨三个织造周期存在源文歧义 | 把 S0/S1/S2 建为待评审假设，不宣称凸轮规律或周期映射已冻结 | WP-04 必须回查原图并冻结离散位移表，随后才能开始 A42 功能建模 |
| GAP-04 | Filling B 时粘合针允许位置和 E-N/E-R 净空未尺寸闭合 | 提供上下针状态参数和保守退出姿态 | A50/A60 配对验收前 |
| GAP-05 | 接合杆 1/2 的 Y 位置、跨度和驱动侧不完整 | 单独参数化 `rod_y`、工作宽度和驱动侧；生成 E-J1/E-J2 | A61 几何冻结前 |
| GAP-06 | `H_fill`、纱层中心、针距、拉剑厚度和动态纱线裕量未定 | 用工程建议值建立可替换层高表 | A50/A60/A61/A70 加工图前 |
| GAP-07 | 若干运动包络遗漏 | 本计划补充 E-J1、E-BIAS-SUPPLY、E-WARP-TENSION、E-YARN、各驱动包络和 SERVICE 包络 | A00 概念 CAD 评审前全部生成 |
| GAP-08 | 重力轴制动/平衡未分配 | 电机包络保留抱闸或配重接口，并在验证报告中判未冻结 | 电机与安全设计冻结前 |
| GAP-09 | 目标纤维、张力、弯曲半径和接触表面未定 | 纱线接触半径作为带状态参数，不以 CAD 成功代表材料通过 | 纱线接触零件加工图前 |
| GAP-10 | 电机、轴承、丝杠、带和链的正式选型缺少载荷 | 建采购级包络和接口，不伪造寿命结论 | M1 至 M10 选型评审前 |
| GAP-11 | SimpleCADAPI 约束报告只检查放置传播和 connector 残差，不计算机构自由度或约束秩 | 建立独立 `JointContract` 注册表和运动学合同审计；报告中使用“放置已解算”而非“自由度已证明” | 任一数字运动副通过前 |
| GAP-12 | 当前碰撞器只检查单姿态网格穿透，不证明正净空、连续轨迹或完全包含 | 补充保守膨胀包络、实体相交/包含检查、预期 pair 计数和同步轨迹采样 | 任一 5 mm 净空或全行程无碰撞声明前 |
| GAP-13 | 虚拟主相位未包含周期累计状态 | 分离 `ActuatorPhase` 和 `MachineState`，记录周期数、绝对牵引位置、块/筒工位、挂钩库存和纱线状态 | 完整周期和首周期验证前 |
| GAP-14 | 填充纱与粘合纱上游筒子、制动、断纱和换卷接口没有明确所有者 | 分别作为 A60 和 A50 内部供纱子总成独立建模 | A50/A60 子总成完成前 |
| GAP-15 | 公差、挠度、热伸长、磨损和伺服误差未进入可执行净空预算 | 建立最坏情况与 RSS 尺寸链；外部实测/FEA 结果通过证据引用输入 | 制造发布关口前 |

代码应提供两个不同的验证入口：

```text
validate_concept_parameters(...)
validate_manufacturing_release(...)
```

前者允许有来源记录的工程建议值，后者对任何关键未验证参数、未闭合占位表、未验证净空、缺失质量/载荷/公差证据或缺失试验记录失败关闭。

## 4. 建模范围和完整性边界

### 4.1 本阶段要煮沸的 lake

以下工作边界明确、可在仓库内完整实现，不接受“先做 90%”方案：

1. A00 至 A90 的完整 A 级产品树、稳定组件 ID 和精确数量登记表；资料不足时数量状态必须为 unresolved，不能伪造 BOM。
2. [08](08-parts-assembly-and-cad-breakdown.md) 所列关键零件的最低功能特征。
3. 所有规定运动副、零位、限位、运动学合同和必备离散姿态/同步轨迹。
4. E-G、E-N、E-R、E-J2、E-D、E-H、E-T，以及本计划补齐的 E-J1、E-BIAS-SUPPLY、E-WARP-TENSION、E-YARN、各驱动和维护空间。
5. 完整 0 至 360 度执行器相位映射、跨周期累计状态、互锁、传感器确认、故障退出、边界值和错误路径。
6. 概念参数和制造发布参数的完整校验。
7. 产品树、放置/connector 残差求解、独立运动学合同审计、模型 JSON 严格重放、语义等价比较、导出、静态姿态干涉和同步轨迹净空检查。
8. 全部公共构建器和纯逻辑模块的测试；纯参数、姿态和互锁模块目标 100% 分支覆盖。
9. README、运行方法、输出清单、限制和验证报告格式。

### 4.2 当前不可在仓库内煮沸的 ocean

以下工作依赖未知产品需求、外部物理试验或专业分析，不得以视觉 CAD 结果冒充完成：

1. 目标纤维拖纱、弯曲、磨损、张力和上浆剂相容性试验。
2. 正式 FEA、疲劳、模态、轴承寿命、丝杠临界转速和急停动力学签核。
3. 连续接触凸轮、链条多体动力学和柔性纱线物理仿真。
4. 安全等级、电气原理图、PLC/运动控制程序和量产控制柜。
5. 未取得 S0/S1/S2 占位证据前的真实全数量导向块与凸轮制造定义；该项同时是偏斜索引数字功能验证的硬阻塞，不得用代表性几何绕过。
6. 未通过 L0 至 L5 和目标纤维试织前的加工图或量产寿命声明。

Ocean 项目要保留接口、输入字段、失败状态和外部证据链接位置；不在 CAD 中编造结果，也不阻塞其余 lake 的完整实现。

```text
main.py / collision_probe.py ← 应用入口
```

强制规则：

1. `parameters.py`、`inventory.py`、`guide_index_topology.py`、`poses.py`、`machine_state.py` 和 `yarn_topology.py` 只依赖 Python 标准库，不创建几何。
2. 领域模块不得相互导入；跨总成关系通过参数、放置和连接器传递。
3. 领域模块不得创建 `GraphSession`；每次顶层构建只由入口打开一个 session。
4. SimpleCADAPI 的已命名参数全部使用关键字；`union_rsolid(*solids)` 等公开签名要求的可变位置实体参数按签名传递。
5. 标准轴承和齿轮优先使用 `scad.std`；链轮、凸轮和纱线接触件因功能特征特殊而单独建模。
6. 单个制造实体使用 `Part`；焊件、轴承、链、驱动包和多实体机构使用 `Assembly`，不得为凑成一个 `Part` 而合并不相连零件。
7. 重复件只构建一次定义，以不同 component placement 实例化；左右手性件使用独立 part ID。
8. 子总成接口使用 placement connector，不把布尔后易变化的任意拓扑面作为跨模块接口。
9. `solve_assembly_constraints_rassembly(strict=True)` 只作为放置传播和 connector 残差证据；预期关节类型、轴向、限位、驱动量和组件覆盖由 `kinematics.py` 单独审计。
10. 当前静态碰撞报告只有在后端完成、预期组件/pair 全部被检查且无 `mesh_missing/mesh_empty` 时才可作为穿透证据；它不能单独作为正净空或连续运动证据。

### 5.3 产品树和非 BOM 场景

顶层构建结果应分离为：

```text
MachineBuild
├── machine: 当前细节级别的 A00 几何产品树
├── inventory: 与渲染细节无关的权威数量和实例身份登记
├── process_scene: machine + 纱线路径/成型体
├── envelopes: 全部运动、纱线、防护和维护包络
├── state: 当前不可变机器累计状态和执行器姿态
└── validation: 当前构建的判定、证据哈希和未冻结项
```

稳定顶层组件 ID：

```text
a00_skeleton
a10_main_frame
a20_warp_supply
a30_upper_bias_supply
a31_lower_bias_supply
a40_upper_guide_frame
a41_lower_guide_frame
a42_bias_index_drive
a50_binder_system
a60_filling_system
a61_engaging_rods
a70_open_reed
a80_width_hooks

```

纱线和包络不进入制造 BOM，避免质量、碰撞和导出清单把工艺辅助几何当作机器零件。`inventory.py` 是数量和实例身份的权威来源；`REPRESENTATIVE` 可以降低显示几何数量，但不得改变 inventory。任何未冻结数量都以 unresolved 记录，并阻止 BOM/质量/惯量和 `FULL` 发布。

## 6. 参数、细节级别和失败策略

### 6.1 参数状态

关键参数不是裸浮点数，应至少携带：

```text
value
unit
evidence: pdf_explicit | figure_reconstruction | engineering_completion
status: proposal | validated
source
revision
external_evidence_id
```

派生量只保留一个计算源。例如 `s=p/tan(theta)`、导向位置、拉剑最小行程和三个填充面由属性计算，不复制到多个模块。数量登记至少覆盖经纱端数、上下偏斜筒子/承载板/链节、导向块、针、填充和粘合筒子、筘片、挂钩、轴承、紧固件和备件；纱线端数、筒工位和导向身份之间必须有守恒校验。

当前产品对象和 canonical model JSON 不应被假定会自动保存任意 `Part`/`Assembly` metadata、验证记录或外部证据。`evidence.py` 必须显式序列化这些内容，并用 model JSON 哈希、源码 revision 和 schema version 防止报告与模型错配。

### 6.2 构建细节级别

| 级别 | 内容 | 允许条件 |
|---|---|---|
| `SKELETON` | 基准、框架、安装接口和最小机构载体 | 概念参数通过 |
| `ENVELOPE` | SKELETON 加所有刚性/纱线/维护包络 | 行程和工程建议限位存在 |
| `REPRESENTATIVE` | A00 至 A90 全部 A 级接口和已闭合功能总成；重复显示几何可降采样，但 inventory 不降采样 | 默认建模级别；未闭合功能明确标为 blocked |
| `FULL` | 按参数生成全部筒子、导向块、筘片、纱线和重复件 | 所有计数和 S0/S1/S2 占位闭合 |

`REPRESENTATIVE` 不是删掉子系统的快捷模式。它必须包含完整 A 级架构和所有关键接口，只减少不影响当前判断的显示实例；它不能用于准确 BOM、质量、惯量或全量碰撞声明。`FULL` 缺少任何数量或占位表时必须给出可操作错误，不得回退到猜测数量。

### 6.3 姿态建模

每个数字样机姿态单独打开 GraphSession，以避免重复 semantic ID 和超大操作图。用于几何构建的最低关键姿态为：

```text
HOME
HOOK_INSERT
HOOK_RETRACT
GUIDE_UNLOCK
GUIDE_CAPTURE
INDEX_S0
INDEX_S1
INDEX_S2
GUIDE_SEAT
GUIDE_LOCK
FILL_A_PICK
FILL_A_RETURN
FILL_A_CAPTURE
FILL_A_BEAT
NEEDLE_SWAP
FILL_B_PICK
FILL_B_RETURN
FILL_B_CAPTURE
FILL_B_BEAT
TAKEUP_START
TAKEUP_END
SERVICE
```

生命周期状态另含 `THREADING`、`PRIMED`、`FIRST_CYCLE`、`PRODUCTION`、`END_OF_TRAVEL`、`UNLOAD` 和 `RECOVERY`。每个运动状态还要定义急停后的保持状态和安全退出边，不允许用“全部回 HOME”替代恢复设计。

执行器姿态记录 M1 相位、导向占位、针 Z、拉剑 Y、接合杆 1 Z、接合杆 2 X/Z、筘 X/Z、挂钩插入量、夹爪开合/锁紧量和牵引 X。`MachineState` 另记录 `cycle_index`、绝对牵引位置、导向块与筒子身份置换、已插挂钩位置/库存、纱线穿线路径、夹具载荷归属、传感器确认、故障锁存和生命周期。

只有局部周期执行器坐标允许 `0°` 与 `360°` 等价。完整 `MachineState` 在周期后已经增加周期数、牵引量、挂钩和纱线单元，不能判为相同。

连续凸轮、链条和纱线物理不在 SimpleCADAPI 约束求解器内伪装实现。它们以经验证的离散轴位置、普通转动/移动副和保守包络表达。

4. 分别补充 E-M1 至 E-M10、同步轴、电缆拖链、防护门和各维护对象的命名 SERVICE 包络；每个包络只有一个生产模块。
5. 建立显式允许接触清单；不通过大范围 exclusion 隐藏碰撞。
6. 对多个完整周期离散推进每根纱线身份，计算各状态的路径长度变化、张力摆臂/恒力回收器所需行程、偏斜边缘绕钩折叠、三填充纱圈交接和粘合纱贯穿路径。

退出条件：每个活动机构和维护对象均有独立非 BOM 包络；所有禁入矩阵组合可自动遍历；任何参数变化会重新生成受影响包络。纱线 ID/端数守恒、路径连续，任何周期的放纱/回收需求不超过对应补偿行程；未知材料伸长和张力能力阻止制造发布。

### WP-12 数字分析、净空和证据闭环

任务：

1. 对每个子总成执行 connector 残差和 `JointContract` 覆盖审计，报告两类证据，不把前者称为 DOF 证明。
2. 建完整 expected-component/expected-pair 清单；后端未完成、网格缺失、pair 数不足或几何为空时数字净空关口失败。
3. 对每条同步轨迹自适应采样；用实体相交/包含检查和按 `C_dyn` 膨胀的保守 keepout 判断正净空，不只检查表面穿透。
4. 建 X/Y/Z/相位尺寸链的最坏情况和 RSS 预算，纳入制造误差、热伸长、磨损、外部挠度和伺服跟随误差。
5. 从精确 inventory、实体体积、质心和材料密度计算质量/质心；惯量能力不足时使用明确外部分析输入并阻止发布，不由体积猜测。
6. 建 preliminary load input：移动质量、等效惯量、自由针长、夹持面积、支承跨距和力臂；正式 FEA/寿命仍引用外部证据。
7. 导出模型语义签名：产品层级、组件 ID/数量、placement、connector、constraint、tag、材料、体积和包围范围；重放后逐项比较。
8. 生成版本化 evidence manifest，绑定模型 SHA-256、源码 revision、参数、验证结果、外部证据 ID、跳过项和发布判定。
9. 对 A90 计算防滑裕量和分段接触压力；对纱线系统复核多周期路径长度、补偿行程和身份守恒结果。

数字概念默认 `C_dyn=5 mm`，状态为工程建议，但任何配置都必须满足 `C_dyn>=5 mm`，不得通过调低阈值获得通过。每个非接触刚性件 pair 在每个适用姿态和轨迹区间必须满足：

```text
min_clearance_worst_case >= C_dyn >= 5 mm
```

`min_clearance_worst_case` 必须扣除制造公差、热伸长、磨损、结构挠度和伺服跟随误差。工艺接触 pair 只能按命名接触区域、允许相位和允许穿透单独豁免，并进入 evidence manifest；不得豁免整个机构。

退出条件：所有声明的分析都有输入、算法、版本和结果；缺失能力/数据明确失败关闭；每个 pair/相位都有最坏净空和判定；静态碰撞、正净空、同步轨迹和物理试验状态在报告中分栏，不互相替代。

### WP-13 D2 至 D5 数字集成和周期验证

任务：

1. `assembly.py` 组装 A00，固定骨架并把各 A 级 `machine_mount` 约束到发布接口。
2. 所有子总成和根总成执行 connector 残差求解与关节合同审计，拒绝未覆盖组件。
3. 逐一构建全部关键姿态和同步轨迹；校验执行器相位环绕以及跨周期累计状态变化。
4. 对 [02](02-spatial-layout-and-envelopes.md) 和 [07](07-timing-interlocks-and-control.md) 的每条禁入/互锁建立测试。
5. 对关键姿态和轨迹执行 WP-12 净空检查；碰撞后端不可用会阻止数字净空关口，不降级为通过。
6. 覆盖 THREADING/PRIMED/FIRST_CYCLE/PRODUCTION/END_OF_TRAVEL/UNLOAD/RECOVERY 以及每类故障的安全退出。
7. 导出 canonical model JSON，严格导入/重放并执行语义签名等价比较。

退出条件：A00 至 A90 全部存在；所有关键姿态、同步轨迹和生命周期状态可构建；周期没有未覆盖相位；制造树不含工艺和包络实体；验证报告列出所有允许接触、失败关闭项和未冻结项。D2 至 D5 是仓库内数字成熟度，不等于 09 的物理 L2 至 L5 验收。

### WP-14 CLI、输出和发布关口

任务：

1. 支持 `--pose`、`--detail`、`--include-yarns`、`--include-envelopes`、`--manufacturing-gate` 和输出目录。
2. 输出 model/session JSON、inventory/BOM JSON、evidence manifest、machine/envelope STEP、scene STL、验证 JSON 和可选 FCStd。
3. FreeCAD 不可用只影响 FCStd，不影响基础建模和 STEP；状态必须清楚报告。生成 FCStd 后需重新打开并核对层级/对象/关节数量，逐关节报告 native equivalent、native partial 或 metadata only。
4. CLI smoke test 使用临时目录，不污染仓库输出目录。
5. 补齐运行、限制、证据状态和变更影响说明。

退出条件：从干净环境运行一条命令可得到可重放模型和哈希绑定的证据报告；所有输出具有状态、姿态和细节级别版本名；失败返回非零并给出具体关口。

## 8. 验证矩阵

### 8.1 参数和边界

必须覆盖：

1. `p<=0`、`n<2`、`theta<=0`、`theta>=90°`、非有限数和负间隙。
2. `X_G<X_N<X_R<0<X_T` 的每一种错序。
3. 三个填充面不对称、`H_fill<=0` 和通道净高不足。
4. `W`、导向跨度和边缘余量不一致。
5. S0/S1/S2 数量不等、重复编号、缺号、双占位和无接收位。
6. 行程小于工作宽度加两侧退出/拾纱裕量。
7. 工程建议值误入制造发布关口。

### 8.2 零件和子总成

每个公共构建器至少验证：

1. 返回类型、正体积和预期实体数。
2. 必须标签和 placement connector。
3. 独立制造件与多实体总成的边界正确。
4. 左右/上下手性 ID 和镜像方向正确。
5. 全行程机械零位、端点和一个中间点。
6. connector 残差报告无未解组件和超差 residual；关节合同覆盖审计单独通过。
7. model JSON strict replay，并且产品树、数量、placement、connector、constraint、tag、材料和关键几何签名等价。

### 8.3 姿态和互锁

必须逐条编码 07 的允许条件，并覆盖成功和失败分支：

1. 导向索引只在拉剑、针、筘和接合杆 2 退出时允许。
2. 拉剑只在锁爪到位且三通道无遮挡时进入。
3. 筘前进只在纱圈已捕获、针位允许时发生。
4. 针换位只在筘下降、拉剑退出时发生。
5. 偏斜索引只在挂钩入轨、插入滑块退出后发生。
6. 牵引只在第二次打纬完成且所有侵入件安全时发生。
7. 命令状态和确认状态分离；锁爪、链制动、挂钩存在、夹具锁紧、针/拉剑/筘到位和左右牵引差均由传感器确认字段控制。
8. 覆盖导向扭矩超限、拉剑不到位、筘力超限、针异常、断纱、链/块错相、左右牵引差、缺钩、传感器失效和急停的锁存与安全退出。
9. 只有局部执行器相位的 `0°` 与 `360°` 等价；完整 `MachineState` 必须反映周期累计变化。负角和大于 360 度角按明确定义归一化或拒绝。

### 8.4 静态碰撞和包络

按姿态检查有物理意义的组件对，不对整机盲目全对全后批量排除。至少包括：

```text
E-G vs E-N/E-R/E-D
E-R vs E-N/E-D/E-J1/E-J2
E-J2 vs E-D
E-H vs guide-index and insertion-slide envelopes
E-T vs all weaving intrusions
E-BIAS-SUPPLY/E-WARP-TENSION/E-YARN vs frame, guards and service volumes
E-M1...E-M10 vs yarn, frame, guards and maintenance volumes
```

SimpleCADAPI 当前静态碰撞只判断当前姿态的网格穿透，不证明正净空、连续运动或完整包含。数字关口还必须检查 expected-component/expected-pair 完整性、缺失网格、实体包含、`C_dyn` 膨胀 keepout 和同步轨迹保守扫掠；柔性纱线接触仍需外部复核。

### 8.5 覆盖率和完成标准

1. `parameters.py`、`inventory.py`、`guide_index_topology.py`、`poses.py`、`machine_state.py`、`yarn_topology.py` 和纯互锁/尺寸链逻辑达到 100% 语句与分支覆盖。
2. 每个领域模块的所有公共构建器至少由一个正常测试和一个相关错误/边界测试触达。
3. `SKELETON`、`ENVELOPE`、`REPRESENTATIVE` 全部构建；`FULL` 同时测试成功路径和证据缺失失败路径。
4. 所有声明的关键姿态、同步轨迹、生命周期和故障恢复路径全部构建，不能只抽测 HOME。
5. 可选 FCStd 路径可因本机无 FreeCAD 明确 skip；被当前发布声明依赖的碰撞/分析后端缺失时必须失败关闭，不得作为通过或普通 skip。

## 9. SimpleCADAPI 使用约束

1. 每个姿态使用一个顶层 `GraphSession`，领域构建器不得嵌套 session。
2. 使用 `make_assembly_rassembly`、`add_component_rassembly` 和 placement connector 建产品结构。
3. 固定、转动和移动副使用公开 assembly constraint；齿轮/带/齿条约束只表达 SDK 支持的标量耦合。
4. 共轭凸轮、链条、丝杠螺纹、纱线和控制状态不伪装成 SDK 可求解接触。
5. 所有已命名 SimpleCADAPI 参数使用关键字；可变位置实体参数如 `union_rsolid(*solids)` 遵循公开签名。
6. 所有意图标签使用规范小写点分词；尺寸和验证状态进入参数/metadata，不编码进 tag。
7. 跨总成装配使用 placement connector；稳定局部特征优先使用 operation output role 和 QL，不依赖布尔后的固定 face index。
8. 每个主要建模步骤输出小型 QL grounding：关键面数量、中心、法向、体积、标签或连接器，不打印完整对象。
9. `export_model_json` 和 `replay_model_json(..., strict=True)` 是每个集成构建的强制基础验证；随后还必须比较语义/几何签名，不能把“能重放”当作“等价”。
10. STEP/STL 导出基于装配投影 compound；FreeCAD 翻译从 canonical model JSON 产生，并单独验证翻译后的层级和关节状态。

以下只估算仓库内架构、CAD 代码、测试、验证和文档，不包含外部试验、采购等待、加工装配和物理调试。

|---|---:|---:|---|

| D0/D1 零件、运动副和关节合同 | 2 至 3 周 | 约 1 至 2 个工作日 | CAD/OCC 调试降低压缩率 |

| A10 至 A90 子总成和 A15 防护 | 6 至 9 周 | 约 3 至 5 个工作日 | 多领域功能几何与接口调试 |

## 11. 实施顺序和并行边界

推荐主路径：

```text
WP-00 → WP-01 → WP-02 → WP-03
        ├→ WP-04 偏斜索引拓扑冻结
        ├→ WP-05 A10/A90
        ├→ WP-08 A50
        ├→ WP-09 A60/A61/A70

WP-04 → WP-06 A40/A41 → WP-07 A20/A30/A31/A42

→ WP-11 包络 → WP-12 数字分析 → WP-13 数字集成 → WP-14 发布
```

WP-04、WP-05、WP-08、WP-09 和 WP-10 可以在公共参数/连接器冻结后并行。WP-04 是 WP-06/WP-07 的硬依赖。WP-08 与 WP-09 先各自验证，二者的 E-N/E-R/E-D 配对净空放在 WP-12，不互设退出依赖。WP-11 必须消费所有机构的真实行程；WP-13 只集成已通过 D1 合同和 WP-12 数字分析的子总成。

首个可执行里程碑不是漂亮整机截图，而是：

1. 一个严格重放且语义签名等价的关键零件包。
2. 一个在机械零位、两端限位和中间位完成 connector 残差/关节合同审计的 D1 运动副。
3. 一份通过占位守恒和身份置换校验的偏斜索引拓扑；没有它不进入功能导向框架里程碑。
4. 一个具有 G-01 至 G-16、真实接口、分阶段运动和包络的 A40/A41 功能框架。
5. 一个包含全部 A00 至 A90 A 级接口、精确 inventory 状态和阻塞项的 `REPRESENTATIVE/HOME` 整机。
6. 全部姿态、轨迹、互锁、故障恢复和包络通过后，才把视觉渲染作为结果展示。

## 12. 概念 CAD 完成定义

只有以下条件全部满足，本文计划才算实施完成：

1. 文件边界、单向依赖和稳定 ID 经测试锁定。
2. A00 至 A90 均由功能零件和明确运动副组成，不存在无说明的纯视觉占位总成。
3. 所有关键姿态、同步轨迹、生命周期、故障恢复、互锁和运动/维护包络可生成并验证。
4. GAP-01 至 GAP-15 均有代码中的显式状态、验证门槛和责任输出，不存在静默默认值；真实零件 G-01 至 G-16 均纳入 A40/A41/A42 几何或接口合同。
5. canonical model JSON 严格重放且语义签名等价，evidence manifest 哈希匹配，CLI 和输出 smoke test 通过。
6. 纯逻辑达到 100% 分支覆盖，所有公共 CAD 构建器均有正常和边界验证。
7. `REPRESENTATIVE` 完整表达 A 级架构和所有已闭合功能；精确 inventory 独立存在；`FULL` 在资料充分时完整生成，在资料不足时准确失败。
8. 数字净空关口对缺失组件、pair、网格、分析输入或后端失败关闭，不能以 warning 代替失败。
9. 验证报告区分“几何构建成功”“D0-D5 数字验证通过”“物理 L0-L5 通过”和“允许进入加工图”，不混淆四者。
10. 任何被标记为 ocean 的外部工作都保留输入、输出和证据链接接口，但不伪造通过结论。

加工图、物理样机和目标纤维验收仍必须通过 [09-materials-tolerances-and-validation.md](09-materials-tolerances-and-validation.md) 的独立关口。
