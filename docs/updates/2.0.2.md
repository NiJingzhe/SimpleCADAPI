# SimpleCADAPI 2.0.2 Update Notes

[中文](2.0.2.zh-CN.md)

> **Experimental release notice:** The capabilities described below are still
> experimental. Breaking changes may be introduced in later releases, so this
> version is not recommended for immediate production use.

SimpleCADAPI 2.0.2 expands the project from an OCP-native geometry API into an
end-to-end, inspectable CAD workflow. The release covers model creation,
parameter and tolerance reasoning, replayable persistence, cross-CAD
translation, browser inspection, assembly verification, and STEP reverse
engineering.

## 1. Cross-CAD Translation

Canonical model JSON can be translated into automation scripts for FreeCAD,
Fusion 360, and SolidWorks. The FreeCAD backend can also write an editable
`.FCStd` document when FreeCAD/FreeCADCmd is available, preserving sketches,
features, parts, assemblies, links, and source selections where supported.
Fusion 360 exports target its Python automation environment. The SolidWorks
backend emits automation scripts and can drive a STEP export via COM. A single
parameterized SimpleCAD model can therefore serve multiple downstream CAD
systems without maintaining separate scripts.

## 2. Browser 3-D Viewer

The `viewer/` application opens generated `.scene.zip` packages without
importing Python or OpenCascade. It renders GLB geometry and CAD edges, provides
orbit/pan/zoom inspection, exposes an assembly/component tree with per-
occurrence visibility controls, and lets users select faces, edges, and vertices
to inspect measured properties and semantic/topological identity.

The Features view displays the replayable operation tree, parameters, output
counts, tags, and embedded source code, including the originating call and
highlighted source range. Scene packages also validate resource sizes and
SHA-256 metadata before loading referenced assets.

## 3. Structured Persistence, Replay, and Source Mapping

Modeling work recorded through `@model` or `GraphSession` can be exported as
canonical model/session JSON and replayed deterministically with
`import_model_json(...)` and `replay_model_json(...)`. A scene export can
package `scene.json`, `model/model.json`, embedded project-relative Python
sources, and GLB/entity assets into one portable artifact.

Every recorded operation captures best-effort source provenance. A feature-tree
node can be traced to the Python file, function call, assignment target, and
line range that produced it. This provides a foundation for automation,
collaboration, regression testing, and versioned model review.

## 4. Physical Units and Tolerance Analysis

Unit-aware variables preserve declared units in the model graph while converting
CAD operations to canonical millimeters and degrees. Expressions infer
dimensions across arithmetic and supported trigonometric operations, reject
incompatible combinations, and retain their parameter graph for replay.

Manufacturing tolerances can be propagated through dimension chains, analyzed
with nominal and bound results, and checked against explicit requirements. The
result supports unit conversion, dimensional chains, and assembly tolerance
studies without reducing the model to unexplained bare numbers.

## 5. Standard Mechanical Parts and Gear Performance

The standard library includes parameterized bolts and nuts, ball-bearing
assemblies, roller-chain sprockets, spur/helical/herringbone gears, internal
ring gears, racks, cycloidal discs, and bevel gears. These factories return
ordinary SimpleCAD shapes or assemblies, so results can be transformed,
tagged, combined, serialized, translated, and exported like custom geometry.

Gear construction and standard-library graph tracking were also optimized;
representative gear workloads are reported to complete in about one-third of
their previous time.

## 6. Assemblies, Meshes, and Collision Verification

Parts, components, connectors, placements, and assemblies can be persisted as a
structured product tree with fixed, revolute, prismatic, gear, belt, and
rack-and-pinion constraints. Constraint solving and residual inspection make
assembly relationships measurable. Render meshes and edge meshes are generated
for scene assets and downstream inspection.

The optional `simplecadapi[collision]` extra adds static, current-pose mesh
penetration checks through `python-fcl`, with configurable component scopes,
penetration tolerances, contact reporting, and non-fatal backend warnings. This
first verifier checks mesh contact penetration; it does not yet solve motion or
detect every complete-containment case.

## 7. STEP Inspection and Reverse Engineering

The `simplecad-brep` CLI and `simplecadapi.inverse_engineer.brep` API inspect
STEP BREP files and report volumes, surface areas, bounds, topology counts, and
geometric primitive labels. Bidirectional comparisons can apply a hard gate
based on geometric point-set equality and a geometry-labelled face-edge-vertex
incidence graph, rather than relying only on a volume delta.

The toolkit also renders consistent STEP views and compares sampled physical
slices with XOR overlays. These diagnostics help verify whether a reconstructed
part agrees with the original in both geometry and topology.
