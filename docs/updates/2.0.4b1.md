# SimpleCADAPI 2.0.4b1 Update Notes

[中文](2.0.4b1.zh-CN.md)

> **Beta release notice:** These changes are being validated before the final
> 2.0.4 release. Review generated CAD documents before using them in production.

SimpleCADAPI 2.0.4b1 improves FreeCAD document semantics, assembly reliability,
boolean-union behavior, and standard bearing reuse.

## 1. Semantic FreeCAD Documents

The FreeCAD translator now maps source assignment targets and modeling intent to
human-readable object labels while retaining canonical node identifiers for
stable replay and traceability. Translated documents organize visible geometry
into a product-oriented tree instead of exposing a flat list of graph operations.

The Tree View exposes one resolved product root for assembly models, or the
standalone geometry roots for non-product models. Construction objects,
`App::Link` source definitions, and preview compounds remain available for
recomputation without appearing as duplicate top-level models.

## 2. FreeCAD Assembly Stability

Flexible `Assembly::AssemblyLink` occurrences now restore complete native Joint
ViewProviders for copied constraints. Activating a translated assembly keeps
solver-visible joints redrawable and avoids the previous joint-placement redraw
failure.

Occurrence generation and final document persistence now preserve the intended
part, component, connector, joint, material, and visibility relationships in the
saved `.FCStd` document.

## 3. Reliable Boolean Union Semantics

`union_rsolid(...)` now defaults to the normal OCC fuse path. `glue=True` is an
optional optimization: if GlueShift returns multiple solids, SimpleCAD
automatically retries with GlueOff and uses the fallback operation's topology
history.

Face-area contact and positive-volume overlap can produce one manifold solid
without callers introducing artificial overlap. Edge-only, vertex-only, and
point/curve tangencies remain explicit errors because they do not form one
manifold solid. Explicit fuzzy tolerances must be finite and non-negative; they
may bridge a real small gap when that approximation is intentional.

## 4. Standard Fused Bearings and BLDC Migration

`scad.std.bearing.make_ball_bearing_rassembly(...)` can fuse decorative rolling
elements into the outer-ring body while retaining the inner/outer revolute joint.
The fused mode exposes only `outer_ring` and `inner_ring` as solver bodies,
records its simplification in bearing metadata, and supports material assignment.
Internal Part identifiers are namespaced by `assembly_id`, allowing several
bearing sizes in one `GraphSession` without identifier collisions.

The integrated BLDC actuator now uses the standard-library bearing factory for
all motor, interstage, planet, and output bearings. Its generated FreeCAD model
contains eleven bearing instances; each has one fused outer-ring solid, one
inner-ring solid, and no unconstrained ball bodies in FreeCAD Simulation.

## 5. Verification

The release adds regression coverage for face-touching unions, curved overlapping
inputs under glue optimization, non-manifold edge and tangent contact, invalid
fuzzy tolerances, fused standard bearings, repeated bearing definitions, BLDC
bearing contracts, and translated FreeCAD assembly activation.
