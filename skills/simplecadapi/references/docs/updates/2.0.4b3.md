# SimpleCADAPI 2.0.4b3 Update Notes

[Chinese](2.0.4b3.zh-CN.md)

> **Beta release notice:** Validate generated definitions, assembly constraints,
> and manufacturing geometry before production use.

SimpleCADAPI 2.0.4b3 adds reproducible product build boundaries and a persistent,
crash-safe cache spanning whole parts and incremental assembly solves.

## 1. Durable part and assembly definitions

`@scad.part` builds exactly one physical single-solid part and returns a
`PartBuildResult`: runtime `Part`, `PartDefinition`, graph/session state, model
and session JSON, interface differences, and a per-build `CacheReport`. Its
content-derived key covers normalized arguments, builder source, declared file
inputs, revision, tolerance profile, and generator/ABI profile.

`@scad.assemble` requires explicit external `PartDefinition` or nested
`AssemblyDefinition` inputs. Repeated instances share immutable definitions;
closed validation rejects missing, unused, cyclic, conflicting, or incompatible
references. Definitions round-trip independently from process-local runtime
objects.

## 2. Incremental assembly solve

Assembly state records component dependencies and public connector interfaces.
Changes to geometry, connectors, connector bindings, material, or a nested
assembly's forwarded connector propagate only through affected dependency paths.
Unchanged component placements can be restored from cache, but every restored
placement still passes constraint-residual verification before it is accepted.

## 3. PRT reuse

In `read_only` and `read_write` modes, calls to the same decorated `@scad.part`
builder and build key reuse one runtime PRT with zero cache I/O. Concurrent
same-key calls share one build. `off` and `refresh` preserve their explicit
rebuild semantics.

Durable whole-part bundles remain the cross-run boundary. A newly decorated
builder or later process restores an unchanged PRT from its validated bundle and
creates fresh runtime graph provenance. Corrupt records or objects degrade to
misses and are quarantined before recomputation.

## 4. Crash-safe content store and policy

The shared CAS uses canonical closed records, SHA-256 objects, atomic writes,
per-key locks, stale-lock recovery, and object deduplication.

One `CachePolicy` controls part and assembly caching. Precedence is explicit API
argument, environment, `[tool.simplecadapi.cache]`, then defaults. The supported
modes are `off`, `read_only`, `read_write`, and `refresh`.

## 5. Cache diagnostics CLI

The new `simplecad-cache` command emits stable JSON:

```text
simplecad-cache status [--namespace NAME]
simplecad-cache verify [--namespace NAME] [--repair]
simplecad-cache prune [--apply]
simplecad-cache clear [--namespace NAME] --yes
```

Inspection and default prune are read-only. Explicit `--repair`, `--apply`, or
`--yes` is required to mutate state. `verify` always validates record identity,
object presence, byte length, and SHA-256. Namespace clearing preserves objects
still referenced elsewhere.

## 6. Native render crash isolation

On macOS, VTK 9.5's Cocoa offscreen backend can terminate the interpreter with
`SIGSEGV` after repeated or concurrent render-window use. Inspection and SDK
screenshot calls now tessellate in the caller, then render through one-shot VTK
workers guarded by a cross-process lock. Completion markers distinguish a
finished image from a partial native crash; incomplete workers retry, while a
post-write teardown crash cannot terminate the modeling or test process.

## 7. Verification


Regression coverage exercises artifact schema closure, deterministic IDs and
hashes, atomic concurrent write deduplication, corruption quarantine, all cache
modes, in-process same-key PRT reuse, concurrent PRT build deduplication,
cross-wrapper persistent part restore, interface invalidation, assembly
definition DAGs, incremental dependency propagation, residual verification,
and nested connector changes.

The representative external-reference gear-train smoke builds two cached parts,
solves repeated and nested assembly instances, exports an independent assembly
definition archive, reloads it, materializes it, and verifies nested constraint
residuals.
